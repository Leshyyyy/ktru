# AI-классификатор КТРУ — как команда работает с Claude

Oct 25, 2026

У каждого из пятерых свой Claude Pro — пять отдельных аккаунтов. Общих чатов, общих проектов и общей памяти между ними нет. Поэтому главный принцип:

> **Репозиторий — общая память команды.** Всё, что Claude должен знать, лежит в git: `docs/analytics/`, `contracts/`, `CLAUDE.md`. Договорились в чате или на созвоне — это не существует, пока не попало в репозиторий. В вашем репо это уже правильно устроено: контракты важнее прозы, и Claude читает именно их.

## 1. Инструменты

| Инструмент | Для чего | Кто в основном |
| --- | --- | --- |
| **Claude Code** (входит в Pro: терминал, расширение VS Code / JetBrains, вкладка Code в десктоп-приложении) | Писать и править код, запускать тесты, разбираться в чужом коде, ревью диффа | Jove, Данил, Таир, Донир |
| **claude.ai** (чаты, Projects, артефакты) | Разбор выгрузки каталога, разметка, тексты README, сценарий видео, обсуждение решений | Егор; все — для обсуждений |
| **GitHub** | Задачи, PR, CI, доска | Все |

Установка Claude Code — по инструкции на docs.claude.com, вход своим Pro-аккаунтом. Каждый день: `git pull`, затем `claude` в корне репозитория (или в своей папке).

## 2. Структура репозитория

Что уже есть — без изменений; что добавить на этой неделе — отмечено.

```
ktru/
├── CLAUDE.md            ← добавить: общие правила для Claude (шаблон в папке «шаблоны»)
├── README.md            ← Егор: запуск, curl-примеры, метрики
├── docker-compose.yml   ← добавить, Данил
├── .env.example         ← добавить, Данил
├── contracts/           ← есть: openapi.yaml, schema.sql, ml_contracts.py, stub_pipeline.py, fixtures/
├── docs/                ← есть: Sphinx, analytics/, contracts/, guide/
│   └── team/            ← добавить: «Распределение задач», «Как работаем с Claude», макеты экранов
├── backend/             ← добавить, Данил: app/ (FastAPI), tasks/ (Celery), migrations/   + CLAUDE.md
│   └── files/           ← Донир: разбор xlsx/csv/pdf, экспорт   + CLAUDE.md
├── ml/                  ← добавить, Jove: extract, embed, retrieve, rerank, calibrate, evaluate   + CLAUDE.md
├── frontend/            ← есть (PR #2), Таир   + CLAUDE.md
├── data/                ← в .gitignore: выгрузка КТРУ, разметка, веса (ссылка на скачивание — в README)
└── tests/e2e/           ← Донир
```

У каждого своя папка: пять Claude Code не правят одни и те же файлы. Пересечения — только через `contracts/`, а их меняет владелец отдельным PR.

**Документы из этого пакета** положите в `docs/team/` и добавьте в `toctree` в `docs/index.md` — иначе сборка Sphinx с `-W` упадёт на «документ не входит в оглавление».

## 3. CLAUDE.md

Claude Code сам читает `CLAUDE.md` в корне и в папке, где работает. Это единственный способ, чтобы пять разных Claude писали код одинаково.

- **Корневой** — суть продукта, где документы, команды, правила git и запреты. Шаблон — в папке «шаблоны». Владелец — Егор.
- **В каждой папке** (`backend/`, `backend/files/`, `ml/`, `frontend/`) — структура, как запускать тесты, частые ошибки. Пишет владелец зоны.
- Claude дважды сделал одну и ту же ошибку → одна строка в `CLAUDE.md` своей папки.

## 4. Как ставить задачу Claude

Одна задача = одно требование FR из «Распределения задач». Шаблон:

```
Задача: FR-6.4 — ручная правка кода (ведущий Данил).
Контекст: contracts/openapi.yaml — PUT /items/{item_id}/decision; contracts/schema.sql — decisions,
confirmed_examples, v_item_final; docs/analytics/14-extras.md — пункты 2.4 и 2.7.
Что сделать: эндпоинт, запись решения, upsert в confirmed_examples только для via=manual.
Готово, когда: тесты на 200, 404 (код не из версии каталога задачи), 409 (позиция pending),
совпадение с rank 1 = confirm; ответ проходит проверку по схеме Item из openapi.yaml.
Ограничения: contracts/ не меняй. Сначала план, код — после моего ок.
```

| Приём | Когда |
| --- | --- |
| Режим планирования (Shift+Tab) | Любая задача больше одного файла |
| `/clear` | Между задачами — старый контекст мешает и тратит лимит |
| `/compact` | Длинная задача, контекст разросся |
| «Сначала тест, потом код» | Парсеры, статусы, счётчики, экспорт |
| «Прочитай раздел X файла Y» | `openapi.yaml` — 55 КБ, не давайте читать целиком без нужды |
| Запрет чтения `data/` в `.claude/settings.json` | Выгрузка КТРУ и веса огромные |
| «Сверь мой дифф с openapi.yaml и schema.sql» | Перед каждым PR |
| Скриншот макета в запрос | Таиру: «приведи карточку к 05\_Карточка\_позиции.png, не меняя логику» |

## 5. Лимиты Pro в финальную неделю

Лимит общий для claude.ai и Claude Code, расходуется окнами по несколько часов плюс недельный потолок. В последние дни узким местом станет лимит, а не время.

- Тяжёлое (новый модуль, большие правки) — в начале окна, мелочи — в конце.
- Упёрлись в лимит — делайте то, что не требует Claude: ручной прогон приёмки, разметка, ревью чужого PR, README. Напишите в чат, когда окно обновится.
- Не держите один бесконечный чат: каждое сообщение в длинной истории дороже.
- Модель по умолчанию подходит для большинства задач; самые сильные модели расходуют лимит быстрее — включайте их для архитектуры и тяжёлой отладки.
- Донир — запас лимита команды: в 30–31.10 рутинные исправления уходят ему.

## 6. Git и ревью

- `main` — только релизы; работа идёт в `dev`. В `dev` — только через PR, CI зелёный.
- Ветка на задачу: `feat/fr-6.4-decision`, `fix/export-encoding`. PR до ~400 строк.
- В описании PR: какие FR закрывает, как проверить; для фронта — скриншот.
- Ревьюер — тот, чью часть задевает PR («Смежное»); для `contracts/` — обе стороны.
- **Автор коммита — человек.** Сейчас коммиты фронта подписаны `Claude <noreply@anthropic.com>`. Настройте `git config user.name` и `user.email` на себя, Claude пусть остаётся строкой `Co-Authored-By` в конце сообщения. На защите спросят, кто что делал, — история git должна это показывать.
- Код от Claude коммитит тот, кто его прочитал и понимает. «Claude так написал» — не ответ жюри.

## 9. Безопасность

- Ключи LLM — только в `.env` (в `.gitignore`) и в секретах GitHub Actions; в чат с Claude не вставлять.
- Не включать автоподтверждение для `git push --force`, удаления веток, `DROP` в базе — пусть Claude спрашивает.
- Реальные спецификации в разметке — без названий заказчиков и контактов.
- Текст позиции в промпте LLM — только как данные в разделителях (правило из раздела 10 аналитики).

## 10. Подготовка к этапу 2 (48 часов очно)

- `docker-compose up --build`, тесты и `ml.evaluate` запускаются одной командой каждая.
- `CLAUDE.md` во всех папках актуальны — Claude с первой минуты знает проект.
- У каждой зоны есть второй человек: Донир — разбор файлов и тесты, Данил и Таир знают API друг друга, Егор — данные и метрики Jove.
- В первые 2 часа очного этапа: Егор разбирает новое задание и пишет FR в формате этого пакета, остальные читают и задают вопросы; потом — правка контрактов и параллельная работа.
