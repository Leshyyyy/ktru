# AI-классификатор КТРУ — описание интерфейса

Oct 25, 2026 · по сценарию `docs/analytics/02-scenario.md` и контракту `contracts/openapi.yaml`

## Общее

Десктопное веб-приложение для специалиста по закупкам: загрузить спецификацию → проверить колонки → дождаться подбора → проверить спорные позиции → выгрузить файл с кодами. Главное — потратить время только на жёлтые и красные позиции. Целевая ширина 1440 px, минимальная 1280 px; таблица и карточка позиции должны оставаться рабочими на 768 px (карточка открывается на всю ширину). Тёмная тема не нужна. Авторизации нет.

Макеты — «Экраны.html» (открыть в браузере) и «Экраны.pdf», PNG каждого экрана — в папке «Скриншоты экранов». Коды КТРУ и числа условные.

**Как соотносится с фронтом в репозитории.** В ветке `feat/frontend-mock` уже есть экраны на Mantine: `UploadPage` (экраны 1–2), `JobsPage` (7), `JobPage` (3–4), `ItemDrawer` (5–6), `QualityPage` (8). Макеты — ориентир по визуалу и мелочам поведения, а не повод переписывать: стиль переносится темой Mantine (`createTheme`: основной цвет, шрифт, радиус) за полдня. Экран 9 «Каталог» во фронте отсутствует — делается, только если останется время.

### Навигация

- Верхняя панель: логотип, «Задачи», «Новая загрузка», «Качество», «Каталог»; справа — версия каталога и режим работы из `/config` (CPU / реранкер / LLM вкл. или выкл.).
- Хлебные крошки: «Задачи / Спецификация\_оргтехника.xlsx».
- Пока `GET /health` отдаёт `ready: false` — плашка «Система готовится: загружаются модели», кнопка «Начать обработку» неактивна.

### Визуальный язык

| Элемент | Решение |
| --- | --- |
| Шрифт | Onest — интерфейс; JetBrains Mono — коды КТРУ и числа |
| Основной цвет | Тёмно-бирюзовый `#0E6B5C`; акцент выбора — лаймовый `#E4F7A8` |
| Фон / поверхности | `#F4F6F3` / белый, линии `#DDE3DF`, скругление 10 px |
| Код КТРУ | Часть ОКПД2 жирная, суффикс светлее: **26.20.11.110**-00000001 — видно, что соседние коды отличаются только хвостом |

### Уверенность, статусы, флаги

Цвет никогда не работает один: у статуса подпись, у уверенности число. Зону (`band`) считает бэкенд по порогам из `/config`.

| Зона | Порог | Цвет |
| --- | --- | --- |
| green | ≥ 85% | бирюзово-зелёный |
| yellow | 50–84% | янтарный |
| red | < 50% | коралловый |

| `ItemStatus` | Подпись |
| --- | --- |
| `pending` | В очереди |
| `processed` | Обработана (зелёная зона, человек не смотрел) |
| `needs_review` | Требует проверки (ниже зелёного порога) |
| `confirmed` | ✓ Подтверждена |
| `corrected` | Исправлена |
| `failed` | Ошибка (с текстом `error`) |

| Флаг (`ItemFlag`) | Подпись в интерфейсе |
| --- | --- |
| `required_missing` | ⚠ нет обязательной характеристики КТРУ |
| `archived_code` | ⚠ код в архиве каталога |
| `low_extraction_confidence` | ⚠ атрибуты извлечены неуверенно |

Группа повторов (`group_id`, `group_size > 1`) — бейдж «+N таких же», клик фильтрует таблицу по группе.

### Состояния, которые нужны везде

Загрузка (скелетоны), пусто с подсказкой, ошибка с `message` из ответа и кнопкой «Повторить», «система готовится», режим `degraded` — ненавязчивая плашка «Без LLM: работают правила и реранкер».

## 1. Новая загрузка — файл

![Загрузка файла](Скриншоты%20экранов/01_Загрузка_файла.png)

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Переключатель | «Файл спецификации» / «Быстрая проверка до 20 строк» | Второй режим — поле для строк → `POST /classify`, результат сразу в таблице |
| Зона перетаскивания | XLSX, CSV, PDF, до 50 МБ, до 1000 позиций | `POST /files` |
| Карточка файла | Имя, размер, листы, строк на листе | Убрать файл |
| Повторный файл | Если пришёл `duplicate_of_job_id`: «Этот файл уже обрабатывался … — открыть результат» | Переход в ту задачу |
| Ошибка | 413 / 415 / 422 — текст `message` как есть | — |
| Справа | «Как это работает» в 3 шагах, версия каталога | «Далее: колонки →» |

## 2. Сопоставление колонок

![Колонки](Скриншоты%20экранов/02_Колонки.png)

Главный для качества экран: ошибка в колонке наименования портит весь подбор.

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Плашка раскладки | Если пришёл `layout_hint`: «Раскладка подставлена из прошлого файла с такими же заголовками» | — |
| Лист и строка заголовков | Выпадающие списки, по умолчанию `header_row` из ответа | Смена пересчитывает предпросмотр |
| Предпросмотр | 10 строк, буквы колонок и номера строк; над колонками — роли: Наименование, Описание, Характеристики, Кол-во, Ед. изм., Не брать (`suggested_role`). Строки до заголовка и «Итого» зачёркнуты | Сменить роль |
| Сводка | Строк данных на листе (`row_count`; для PDF — «станет известно после разбора»), лимит 1000 | — |
| Легенда | Наименование — ровно одна; Описание и Характеристики — сколько угодно; Кол-во и Ед. изм. — не больше одной | — |
| Опции | «Использовать подтверждённые ранее коды» (`use_feedback`), «Использовать LLM, если доступна» (`use_llm`) | — |
| Кнопка | «Начать обработку» — неактивна без колонки наименования | `POST /jobs` → 202 → экран 3. 422 `mapping_invalid` — подсветить колонки |

## 3. Задача — обработка

![Обработка](Скриншоты%20экранов/03_Обработка.png)

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Шапка | Заголовок, плашка режима (`effective_mode = degraded`), подсказка «можно закрыть вкладку» | «Отменить обработку» (`POST /jobs/{id}/cancel`), «Смотреть готовые · N» |
| Прогресс | «288 из 412», полоса (`progress`), «осталось около …» (`eta_seconds`) | Опрос `GET /jobs/{id}` раз в 1,5 с |
| Этапы | В очереди → Разбор файла → Подбор кодов (пачка N из M) → Готово / Готово с ошибками | — |
| Счётчики | Зелёные, Жёлтые, Красные (`summary`), Ошибки (`failed_items`) | — |
| Лента | Последние обработанные позиции с кодом и уверенностью | Клик — карточка позиции |

Фактически это верхняя часть экрана результатов, пока задача идёт: таблица ниже уже заполняется (`GET /jobs/{id}/items` доступен во время обработки). По завершении — баннер «Готово: 255 зелёных · 117 жёлтых · 38 красных» и переход к таблице с фильтром «Сначала спорные».

## 4. Результаты задачи

![Результаты](Скриншоты%20экранов/04_Результаты.png)

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Шапка | Имя файла, статус задачи, «412 позиций · проверено 41» | «Подтвердить все от 85% · N» (`POST /jobs/{id}/confirm-bulk`, `skip_flagged = true`, диалог с числом); «Выгрузить» с меню форматов: как исходный файл, xlsx, csv, json |
| Счётчики | Всего, Зелёные, Жёлтые, Красные, Проверено (confirmed + corrected) | Клик — фильтр `band` или `status` |
| Фильтры | Поиск по исходному тексту (`q`), «Сначала спорные» (`sort=confidence_asc`), «С предупреждениями» (`flag`), «Ошибки» (`status=failed`) | Фильтры в адресе страницы |
| Таблица | Строка файла, исходный текст + атрибуты (наименование · бренд · модель, бейдж группы), кол-во, итоговый код и название (`final`), уверенность, статус и флаги | Клик — карточка; J / K — строки; Enter — подтвердить |

Серверная пагинация по 50; таблица на 1000 строк открывается ≤ 1 с. При выгрузке, если заголовок `X-Unreviewed-Count` больше 0, — тост «В файле 371 непроверенная позиция».

## 5. Карточка позиции

![Карточка позиции](Скриншоты%20экранов/05_Карточка_позиции.png)

Панель 580 px справа поверх таблицы, выбранная строка подсвечена.

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Шапка | Статус, строка файла и количество, полный исходный текст, флаги, «+N таких же в файле» | ↑ K / ↓ J, закрыть; клик по группе — фильтр `group_id` |
| Атрибуты | Наименование, бренд / модель, характеристики (`extracted`), метод и уверенность извлечения | — |
| Варианты КТРУ | До 3 карточек: код, название, уверенность; сверка характеристик (`characteristic_matches`: ✓ совпало, ✗ не совпало, — нет данных; обязательные помечены); у первого — «Пояснение» (`explanation`), у второго и третьего — «Почему не первый» (`why_not_chosen`) | Клик выбирает вариант |
| Ссылка | «Найти другой код в каталоге», путь обработки (`path`: быстрый / реранкер) | Экран 6 |
| Низ | «Подтвердить вариант 1» (Enter) или «Выбрать вариант N» | `POST /items/{id}/confirm` или `PUT /items/{id}/decision`; затем переход к следующей позиции «Требует проверки» |

Для `pending` кнопки неактивны («позиция ещё обрабатывается», бэкенд вернул бы 409). Для `failed` — текст ошибки и сразу поиск кода: ручной код можно проставить.

## 6. Ручная правка

![Ручная правка](Скриншоты%20экранов/06_Ручная_правка.png)

| Блок | Содержимое | Действия и API |
| --- | --- | --- |
| Поиск | Начало кода или слова, от 2 символов; ищем только в версии каталога задачи | `GET /catalog/search?q=&version_id=` с задержкой 300 мс |
| Результаты | Код + название; выбранный раскрывает характеристики (обязательные — со звёздочкой) | `GET /catalog/items/{code}` |
| Причина | «Почему исправлено» — необязательно, до 500 символов | Поле `reason` |
| Кнопка | «Сохранить код …» | `PUT /items/{id}/decision`; 404 — «Код не найден в каталоге этой задачи» |

Тост после любого решения: «Строка 51 подтверждена · Отменить».

![Задачи](Скриншоты%20экранов/07_Задачи.png)

| Блок | Содержимое | Действия и API |
| --- | --- | --- |

| Блок | Содержимое | Действия и API |

| Показатели | Атрибуты (≥ 90%), top-1 полный код (≥ 85%), top-3 и top-1 по ОКПД2, секунд на 1000 позиций — с целями и отметкой | `GET /quality/latest` |

В видео и на защите — только цифры набора `test`.

## Сценарий для видео (≤ 5 минут)

Загрузить xlsx → показать подставленные колонки → начать обработку и закрыть вкладку → открыть задачу из списка → «Сначала спорные» → карточка картриджа с флагом → найти оригинальный код в каталоге → «Подтвердить все от 85%» → выгрузить как исходный xlsx → экран «Качество» с цифрами `test`.
