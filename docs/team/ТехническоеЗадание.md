# Задача 5. ИИ-классификатор КТРУ

## Ключевые технологии
Классификация, эмбеддинги, массовая обработка

## Проблема
Обработка тендерных спецификаций с сотнями позиций товаров требует ручного сопоставления с кодами КТРУ (Каталог товаров, работ, услуг).

## Ожидаемое решение
Автоматическое извлечение атрибутов товаров и семантическое сопоставление с кодами КТРУ с использованием векторных эмбеддингов.

## Примерный воркфлоу задачи
1. Пользователь загружает файлы со спецификациями товаров (.xlsx, .csv, .pdf)
2. ИИ-модуль извлекает атрибуты товара из неструктурированного текста: наименование, бренд, модель, технические характеристики
3. Семантическое сопоставление извлечённых данных с кодами КТРУ с использованием векторных эмбеддингов и текстовых моделей
4. Массовая обработка: загрузка пакетов товаров (до 1000 позиций за один запрос) с асинхронной обработкой через очередь задач
5. Экран результатов: таблица с товарами, предложенными кодами КТРУ, уверенностью модели (%) и возможностью ручной корректировки

## Критерии приемки
1. Извлечение атрибутов - Корректное распознавание ≥ 90% атрибутов (наименование, бренд, модель)
2. Точность классификации - Сопоставление с КТРУ ≥ 85% на тестовом датасете
3. Массовая обработка - 1000 позиций < 5 минут
4. Вывод уверенности - Отображение % уверенности модели для каждого товара
5. Ручная корректировка - Возможность исправить код КТРУ в интерфейсе
6. Асинхронность - Использование очереди задач для обработки
7. Архитектура - Запуск через docker-compose up --build

## Технический стек
1. Фронтенд - React / Vue.js / Next.js. SPA, адаптивный интерфейс, UX для не-технических пользователей
2. Бэкенд - Python (FastAPI/Django) или Node.js. REST API, бизнес-логика
3. Очереди - Celery / RabbitMQ / Redis. Асинхронная обработка тяжёлых задач
4. База данных - PostgreSQL. Хранение профилей, логов, метаданных
5. ИИ-слой - pgvector / Qdrant / Pinecone. Векторный поиск, эмбеддинги документов

## Общие требования кейс-чемпионата
1. Запуск одной командой: `docker-compose up --build`
2. README.md с пошаговой инструкцией и примерами API-запросов
3. Решение в виде готового Docker-пакета
4. Интерфейс не требует технических знаний для использования
5. Формат: этап 1 (удалённо) — 1 месяц на базовый функционал; этап 2 (очно) — 48 часов на дополнительное задание и защита
6. Результат этапа 1: решение в репозитории + видео (команда, техническое решение, работа приложения) не длиннее 5 минут
