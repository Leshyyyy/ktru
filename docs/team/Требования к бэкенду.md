# AI-классификатор КТРУ — требования к бэкенду

Oct 25, 2026 · по контрактам репозитория github.com/Leshyyyy/ktru

Документ — рабочая памятка для бэкенда (Данил) и разбора файлов (Донир): что реализовать, в каком порядке и где легко ошибиться. Полные схемы запросов и ответов — `contracts/openapi.yaml` (48 примеров), таблицы — `contracts/schema.sql`, вызов ML — `contracts/ml_contracts.py`. **Контракт важнее этого текста.**

## Общие соглашения

| Тема | Правило |
| --- | --- |
| Адреса | Префикс `/api/v1`, JSON, `snake_case` |
| Авторизация | Нет. Все данные видны всем |
| Время и id | UTC, ISO 8601; UUID везде, кроме кода КТРУ (текст) |
| Пагинация | `{items, total, page, page_size}`, `page_size` по умолчанию 50, максимум 200 |
| Уверенность | Число 0–1; зона (`band`) считается на бэкенде по порогам из `/config`: green ≥ 0,85, yellow ≥ 0,50, red ниже |
| Долгие операции | Всё, что дольше 2 с (кроме `POST /classify`), — 202 с идентификатором |
| Ошибки | `{"error": {"code", "message", "details"}}`, `message` по-русски для человека |
| Валидация FastAPI | Переопределить обработчик `RequestValidationError`: отдавать 400 `invalid_request`, а не 422 `{"detail": [...]}`. 422 — только бизнес-ошибки |
| CORS | `expose_headers`: `X-Unreviewed-Count`, `Content-Disposition`; кириллица в имени файла — `filename*=UTF-8''...` |
| Лимит тела | nginx `client_max_body_size` выше 50 МБ, 50 МБ проверяет приложение и отвечает 413 `file_too_large` в нашем формате |

### Коды ошибок

| HTTP | `code` | Когда |
| --- | --- | --- |
| 400 | `invalid_request` | Неверные параметры |
| 404 | `not_found` | Нет файла, задачи, позиции или кода КТРУ (`details.object = ktru_code`) |
| 409 | `invalid_state` | Действие невозможно в текущем статусе; решение по позиции `pending` |
| 413 | `file_too_large` | Больше 50 МБ |
| 415 | `unsupported_file_type` | Не xlsx, csv, pdf (проверка по содержимому) |
| 422 | `file_unreadable`, `mapping_invalid`, `limit_exceeded` | Повреждён / пароль / пуст; неверные роли; > 5000 строк или > 1000 позиций |
| 503 | `not_ready` | Модели не загружены или каталог пуст |
| 500 | `internal_error` | Всё остальное, в `details.request_id` |

## Статусы и правила вычислений

| Сущность | Статусы | Переходы |
| --- | --- | --- |
| Задача `jobs.status` | `queued`, `parsing`, `processing`, `done`, `done_with_errors`, `failed`, `cancelled` | queued → parsing → processing → done / done\_with\_errors; failed, если файл не разобран или ни одна позиция не обработана; cancelled из queued, parsing, processing |
| Позиция `items.status` | `pending`, `processed`, `needs_review`, `confirmed`, `corrected`, `failed` | processed — rank 1 ≥ green; needs\_review — ниже; confirmed / corrected — решение пользователя |
| Решение `decisions` | `kind`: confirm / correct; `via`: manual / bulk | В `confirmed_examples` попадают только `via = manual` |

| Значение | Как считать |
| --- | --- |
| Итоговый код | Последнее решение из `decisions`, иначе `predictions` rank = 1 — только через представление `v_item_final` |
| `progress` | (processed + failed) / total; до конца разбора — 0 |
| `summary` | green / yellow / red по rank 1 обработанных позиций (решения цвет не меняют); confirmed / corrected — пересекаются с цветами |
| `eta_seconds` | По скорости последних пачек (`items.processed_at`) |
| `group_id`, `group_size` | Ключ `наименование|бренд|модель`; `group_id = null`, если в группе одна позиция; без модели не склеивать |
| `green_correction_rate` | corrected / (confirmed manual + corrected) среди зелёных, проверенных человеком |
| `X-Unreviewed-Count` | Позиции без решения пользователя в выгрузке |

## API: что реализовать

| Метод и путь | Главное в поведении |
| --- | --- |
| `POST /files` | Сохранить в том `uploads`, sha256 → `duplicate_of_job_id`; листы, `header_row`, предпросмотр 10 строк, `suggested_role` по словарю заголовков и содержимому; PDF — только первые 3 страницы, `row_count = null`; хеш заголовков → `layout_hint`. Ответ за секунды при любом размере |
| `POST /jobs` | Проверка `column_mapping` (ровно одна `name`, не больше одной `quantity` и `unit`) → 422 `mapping_invalid`; фиксировать `catalog_version_id`; 202 и постановка `parse_file`; 503, если `/health` не ready |
| `GET /jobs`, `GET /jobs/{id}` | Список и статус с `summary`, `progress`, `eta_seconds`, `effective_mode` |
| `POST /jobs/{id}/cancel` | `cancel_requested`; пачки проверяют флаг в начале |
| `DELETE /jobs/{id}` | Удалить задачу и её данные, в том числе во время обработки |
| `GET /jobs/{id}/items` | Фильтры `band`, `status`, `q`, `flag`, `group_id`; сортировка `row_index` / `confidence_asc`; доступно во время обработки |
| `POST /jobs/{id}/confirm-bulk` | `{min_confidence, skip_flagged = true}`; только `processed` / `needs_review`; `via = bulk`; можно во время обработки |
| `GET /jobs/{id}/export` | `format = source | xlsx | csv | json` (для pdf `source` = xlsx); исходные колонки из `raw_row` + код, название, уверенность, статус; экранирование формул (в csv — апостроф, в xlsx — строковые ячейки); `allow_unreviewed`; синхронно, пока ≤ 1000 позиций; отменённую задачу можно выгрузить |
| `GET /items/{id}` | Позиция с топ-3, `characteristic_matches`, `why_not_chosen`, флагами |
| `POST /items/{id}/confirm` | Решение confirm, статус `confirmed`, `via = manual` |
| `PUT /items/{id}/decision` | `{ktru_code, reason?}`; код из версии каталога задачи, иначе 404; совпал с rank 1 → это confirm; для `pending` — 409; работает для `failed`; upsert в `confirmed_examples` |
| `POST /classify` | До 20 строк синхронно через тот же `Pipeline` |
| `GET /catalog/search` | `q` ≥ 2 символов, `version_id`, `limit` ≤ 50; по началу кода и по тексту (trigram) |
| `GET /catalog/items/{code}`, `GET /catalog/versions` | Позиция с характеристиками; версии со статусом |
| `POST /catalog/import` | JSONL по схеме `CatalogRow` → `import_catalog` → `CatalogIndexer.index_version` → статус `ready` |
| `POST /quality/run`, `GET /quality/latest` | `{split: dev | test}` → `run_quality` в очереди `ml`; `use_feedback` всегда выключен |
| `GET /stats` | SQL-запросы, без отдельной системы метрик |
| `GET /health`, `GET /config` | База, redis, модели, каталог по отдельности; пороги, лимиты, режим (`extractor`, `reranker`, `device`, `llm_enabled`) |

## Задачи Celery

| Задача | Очередь | Что делает |
| --- | --- | --- |
| `parse_file(job_id)` | io | Читает файл по `column_mapping`, создаёт `items` (`raw_text`, `raw_row`), режет на пачки по 50, раздаёт `process_chunk` |
| `process_chunk(job_id, item_ids)` | ml | `Pipeline.classify_batch` → `predictions` (upsert по `(item_id, rank)`), `extracted`, `flags`, `path`, статус; атомарно `processed_items += n`; обновлять только позиции в `pending` |
| `maybe_finalize(job_id)` | io | После каждой пачки: если processed + failed = total — финальный статус |
| `export_job(job_id, format)` | io | Сборка файла (пока ≤ 1000 позиций вызывается синхронно) |
| `import_catalog(version_id)` | io | Загрузка строк + вызов индексатора ML |
| `run_quality(run_id)` | ml | Прогон набора, запись `eval_runs` |
| `watchdog()` | io, beat раз в минуту | Задачи в queued / parsing / processing без обновлений > 5 мин → заново поставить позиции `pending` |

Надёжность: ретраи `process_chunk` 5, 20, 60 с, после третьей неудачи позиции пачки `failed` с текстом; `acks_late` + `worker_prefetch_multiplier=1`; мягкий лимит пачки 120 с, жёсткий 180 с; `ML_WORKER_CONCURRENCY=2` по умолчанию; `worker-ml` грузит модели один раз, пока не готовы — `ready: false`.

## Разбор файлов (Донир)

| Формат | Как | Подводные камни |
| --- | --- | --- |
| xlsx / xls | python-calamine (быстро), openpyxl для экспорта | Несколько листов, объединённые ячейки (верхняя левая), заголовок не в первой строке, подитоги |
| csv | Определение кодировки (UTF-8, UTF-8 BOM, cp1251) и разделителя (`;` `,` табуляция) | Excel по-русски сохраняет cp1251 и `;` |
| pdf | pdfplumber: таблицы, иначе строки; повторяющиеся заголовки таблицы на новых страницах убрать | Таблица через несколько страниц; OCR только без текстового слоя |

Обязательные тесты: файл без данных → `file_unreadable`; две колонки `name` → `mapping_invalid`; пустое `name` при заполненном `description` → позиция создаётся; текст > 2000 символов обрезается для эмбеддинга, полный сохраняется; > 5000 строк или > 1000 позиций → `limit_exceeded` с подсказкой разбить файл.

## Нефункциональные требования

| Критерий ТЗ | Что делает бэкенд | Как проверяем |
| --- | --- | --- |
| 3. 1000 позиций < 5 минут | Пачки по 50, два процесса `ml`, пачковые вставки | Файл на 1000 строк, стеновое время ≤ 240 с |
| 4. Уверенность | `band` и `confidence` у каждой обработанной позиции | Тест ответа `GET items` |
| 5. Ручная корректировка | `confirm`, `decision`, `confirm-bulk`, `v_item_final` в экспорте | E2E: правка → экспорт с новым кодом |
| 6. Асинхронность | 202 сразу, опрос прогресса | `POST /jobs` < 1 с на 1000 строк |
| 7. `docker-compose up --build` | `migrate` с сидами, модели в образе, готовые эмбеддинги каталога, `.env.example`, режим без LLM | Чистая машина без GPU и ключей; amd64 и arm64 |
| Общее: 50+ страниц без 504 | PDF разбирается в задаче, предпросмотр — 3 страницы | PDF на 60+ страниц |
| Общее: README | Пошаговый запуск, curl для `/files`, `/jobs`, `/items`, `/decision`, `/export`, `/classify` | Проверяющий повторяет команды |
