# 7. ML-контракты

Бэкенд вызывает всю ML-часть одним методом `Pipeline.classify_batch`, а внутри он состоит из пяти взаимозаменяемых компонентов. Полные типы и интерфейсы — в файле `ml_contracts.py` (pydantic + Protocol). ML-команда реализует их, а бэкенд с первого дня работает с заглушкой `StubPipeline`, которая возвращает правдоподобные детерминированные ответы.

| Компонент | Метод | Вход → выход | Реализации |
| --- | --- | --- | --- |
| `AttributeExtractor` | `extract_batch` | `RawItem[]` → `ExtractedAttributes[]` | `rules`, `llm`, `hybrid` |
| `Embedder` | `embed` | `str[]` → `float[][]` (нормированные, размерность из конфига) | локальная мультиязычная модель |
| `Retriever` | `search_batch` | `SearchQuery[]` → `Candidate[][]` (топ-20) | гибрид: pgvector + trigram/полнотекст + подтверждённые примеры |
| `Reranker` | `rerank_batch` | `(ExtractedAttributes, Candidate[])[]` → `RerankResult[]` | `none`, `cross_encoder`, `llm` |
| `ConfidenceCalibrator` | `predict` | `dict[str,float]` признаков → `float` 0–1 | логистическая регрессия / изотоническая калибровка |

**Ключевые типы данных**

- `RawItem`: `item_id`, `text`, `columns` (исходные значения по ролям колонок).
- `ExtractedAttributes`: `name`, `brand`, `model`, `quantity`, `unit`, `characteristics` (словарь), `method`, `field_confidence`.
- `Candidate`: `ktru_code`, `name`, `okpd2_code`, `vector_score`, `text_score`, `fused_score`, `characteristics`.
- `Prediction`: `rank`, `ktru_code`, `name`, `confidence`, `features`, `explanation`, `characteristic_matches` (список «характеристика — ожидается — найдено — статус match / mismatch / missing»).
- `ClassificationResult`: `item_id`, `extracted`, `predictions` (до 3), `path` (`fast` или `rerank`), `timings_ms`.

**Правило маршрутизации.** Позиция идёт по быстрому пути, если `top1_fused` ≥ 0,75 и отрыв от второго кандидата ≥ 0,15. Остальные идут через реранкер. Пороги — стартовые, они подбираются на dev-наборе и хранятся в конфиге.

**Смысл уверенности.** `confidence` каждого из трёх предсказаний — оценка вероятности того, что именно этот код верный, поэтому их сумма не больше 1. Калибратор применяется к признакам каждого кандидата; если сумма вышла больше 1, значения нормируются. Цвет и статус позиции определяет только уверенность первого. Если LLM была нужна, но недоступна, конвейер ставит в результат `mode = "degraded"` — по этому полю бэкенд выставляет `effective_mode` задачи.

**Признаки для калибровки уверенности:** `top1_fused`, `margin_top1_top2`, `vector_score`, `text_score`, `char_match_ratio`, `rerank_score` (если был), `extraction_confidence`, `vec_text_agreement` (совпадают ли первые кандидаты векторного и текстового поиска), `confirmed_vote` (похож ли текст на ранее подтверждённый пример). Набор признаков фиксирован здесь, чтобы бэкенд мог сохранять их в `predictions.features` для последующего обучения.

**Режимы работы (переменные окружения)**

| Переменная | Значения | По умолчанию |
| --- | --- | --- |
| `EXTRACTOR` | `rules` / `llm` / `hybrid` | `hybrid` |
| `RERANKER` | `none` / `cross_encoder` / `llm` | `cross_encoder` |
| `DEVICE` | `cpu` / `cuda` | `cpu` |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | OpenAI-совместимый endpoint (локальный или облачный) | пусто = LLM выключен |
| `EMBEDDER_MODEL` | имя модели эмбеддингов | выбирает ML-команда в первые дни |
| `EMBEDDING_DIM` | число | 1024, должно совпадать со `schema.sql` |

Если LLM недоступна или не задана, конвейер автоматически переходит на `rules` и `cross_encoder` и пишет в задачу `options.effective_mode = "degraded"`, а фронт показывает ненавязчивую подсказку. Проект в этом режиме должен проходить все критерии по скорости.

**Бюджет времени на 1000 позиций** (цель — не более 240 с при лимите организаторов 300 с; цифры — отправная точка, проверяется замером)

| Этап | Бюджет, с | Как укладываемся |
| --- | --- | --- |
| Разбор файла | 10 | Потоковое чтение, без OCR для xlsx и csv |
| Извлечение атрибутов | 60 | Правила для большинства, LLM только для сложных и пачками по 20 |
| Эмбеддинги | 40 | Пачки по 64, короткие тексты, дедупликация одинаковых строк |
| Поиск кандидатов | 30 | HNSW + trigram, пачковые SQL-запросы |
| Реранкер | 80 | Только для не более 20% позиций |
| Калибровка и запись | 10 | Пачковая вставка |
| **Итого** | **230** | Запас 70 с |

**Правило для ML-команды:** если этап не укладывается в бюджет, он сообщает об этом до конца недели 2, а не переносит проблему на бэкенд. Увеличивать число воркеров — вторая мера, не первая.
