# 6. Асинхронная обработка

Задача делится на пачки по 50 позиций, каждая пачка — отдельная Celery-задача, и сбой одной пачки не останавливает всю задачу. API никогда не делает тяжёлую работу сам, поэтому таймаута 504 не бывает.

**Статусы задачи (`jobs.status`)**

| Статус | Когда | Куда может перейти |
| --- | --- | --- |
| `queued` | Создана, ждёт воркера | `parsing`, `cancelled` |
| `parsing` | Разбирается файл, создаются `items` | `processing`, `failed`, `cancelled` |
| `processing` | Пачки обрабатываются | `done`, `done_with_errors`, `failed`, `cancelled` |
| `done` | Все позиции обработаны | — |
| `done_with_errors` | Готово, но `failed_items` > 0 | — |
| `failed` | Файл не разобран или ни одна позиция не обработана | — |
| `cancelled` | Пользователь отменил | — |

**Celery-задачи и очереди**

| Задача | Очередь | Что делает |
| --- | --- | --- |
| `parse_file(job_id)` | `io` | Читает файл по `column_mapping`, создаёт `items`, резает на пачки и раздаёт `process_chunk` |
| `process_chunk(job_id, item_ids)` | `ml` | Прогоняет пачку через ML-конвейер (раздел 7), пишет `predictions`, обновляет счётчики |
| `maybe_finalize(job_id)` | `io` | Вызывается после каждой пачки; если `processed + failed = total`, ставит финальный статус |
| `export_job(job_id, format)` | `io` | Собирает xlsx или csv; API вызывает её синхронно, пока в задаче не больше 1000 позиций |
| `import_catalog(version_id)` | `io` | Загружает каталог, считает эмбеддинги, строит индексы |
| `run_quality(run_id)` | `ml` | Прогоняет размеченный набор и пишет метрики |
| `watchdog()` | `io`, Celery beat раз в минуту | Находит задачи в processing без обновлений больше 5 минут (поле updated\_at обновляет триггер) и заново ставит в очередь их позиции со статусом pending |

**Правила надёжности**

- **Ретраи.** `process_chunk` повторяется до 3 раз с паузами 5, 20 и 60 с. После третьей неудачи позиции пачки получают статус `failed` с текстом ошибки, а задача продолжается.
- **Идемпотентность.** Повторный запуск пачки не дублирует данные: запись в `predictions` идёт по ключу `(item_id, rank)`, а уже обработанные позиции пропускаются.
- **Прогресс.** Счётчик `processed_items` увеличивается атомарно (`UPDATE ... SET x = x + n`) в конце каждой пачки. Результаты обработанных пачек доступны через `GET /jobs/{id}/items` уже во время работы.
- **Отмена.** `cancel` ставит `cancel_requested`; пачки проверяют флаг в начале и пропускают работу; текущая пачка доходит до конца.
- **Таймауты.** Мягкий лимит пачки — 120 с, жёсткий — 180 с.
- **Модели.** Воркер `ml` загружает модели один раз при старте и держит в памяти. Пока модели не готовы, `GET /health` отдаёт `ready: false`, а создание задачи — 503 `not_ready`.
- **Параллелизм.** По умолчанию воркер `ml` запускается с конкурентностью 2, число задаётся `ML_WORKER_CONCURRENCY`. Точное значение подбирается замером в неделе 3.
