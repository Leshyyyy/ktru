# 5. API

API — REST, JSON, префикс `/api/v1`. Точный контракт с схемами запросов и ответов — в `openapi.yaml`. Фронтенд может начать работу со второго дня, подняв мок-сервер по этому файлу (раздел 12).

| Группа | Метод и путь | Что делает |
| --- | --- | --- |
| Файлы | `POST /files` | Загружает файл, возвращает листы, предпросмотр и предложенные роли колонок |
| Задачи | `POST /jobs` | Создаёт задачу, отвечает 202 сразу |
| Задачи | `GET /jobs` | Список задач |
| Задачи | `GET /jobs/{id}` | Статус и прогресс (опрос раз в 1–2 с) |
| Задачи | `POST /jobs/{id}/cancel` | Останавливает обработку |
| Задачи | `DELETE /jobs/{id}` | Удаляет задачу и её данные |
| Результаты | `GET /jobs/{id}/items` | Позиции с топ-3, фильтры, сортировка, пагинация |
| Результаты | `POST /jobs/{id}/confirm-bulk` | Подтверждает все позиции выше порога уверенности |
| Результаты | `GET /jobs/{id}/export?format=xlsx\|csv` | Выгружает файл с кодами и уверенностью |
| Позиции | `GET /items/{id}` | Карточка позиции со всеми альтернативами и пояснением |
| Позиции | `POST /items/{id}/confirm` | Подтверждает предложенный код |
| Позиции | `PUT /items/{id}/decision` | Сохраняет ручной код |
| Быстрый режим | `POST /classify` | Синхронная классификация до 20 текстов, для демо и отладки |
| Каталог | `GET /catalog/search?q=` | Поиск по каталогу для ручной правки (автодополнение) |
| Каталог | `GET /catalog/items/{ktru_code}` | Позиция КТРУ с характеристиками |
| Каталог | `GET /catalog/versions` | Версии каталога |
| Каталог | `POST /catalog/import` | Запускает импорт новой версии без передеплоя |
| Качество | `POST /quality/run`, `GET /quality/latest` | Запускает оценку на размеченном наборе и отдаёт метрики |
| Система | `GET /health`, `GET /config` | Готовность моделей и каталога; пороги уверенности, лимиты, режим |

**Соглашения**

- Уверенность всегда число от 0 до 1; в интерфейсе показывается как процент.
- Списки возвращаются в виде `{ items, total, page, page_size }`; `page_size` по умолчанию 50, максимум 200.
- Сортировка позиций: `row_index` (по умолчанию) или `confidence_asc`, чтобы спорные позиции были сверху.
- Ошибки всегда в одном формате: `{ "error": { "code", "message", "details" } }`. Фронт показывает `message` пользователю как есть — бэкенд пишет его на русском и по-человечески.
- Любая операция, которая может идти дольше двух секунд (кроме `POST /classify`), асинхронна и возвращает 202 с идентификатором.

**Коды ошибок**

| HTTP | `code` | Когда |
| --- | --- | --- |
| 400 | `invalid_request` | Неверные параметры запроса |
| 404 | `not_found` | Нет такого файла, задачи, позиции или кода КТРУ |
| 409 | `invalid_state` | Действие невозможно в текущем статусе (отмена завершённой задачи, экспорт неготовой) |
| 413 | `file_too_large` | Файл больше 50 МБ |
| 415 | `unsupported_file_type` | Не xlsx, csv или pdf |
| 422 | `file_unreadable` | Файл повреждён, защищён паролем или пуст |
| 422 | `mapping_invalid` | Не назначена колонка наименования или колонка не существует |
| 422 | `limit_exceeded` | Больше 5000 строк в файле или 1000 позиций в задаче |
| 503 | `not_ready` | Модели ещё не загружены или каталог пуст |
| 500 | `internal_error` | Всё остальное; в `details` — `request_id` для поиска в логах |

**Два правила, о которые легко споткнуться.** FastAPI по умолчанию отвечает на ошибки валидации кодом 422 в своём формате `{"detail": [...]}` — бэкенд переопределяет обработчик `RequestValidationError` и отдаёт 400 `invalid_request`, а 422 остаётся только для бизнес-ошибок. Неизвестный код КТРУ при ручной правке — 404 `not_found` с `details.object = ktru_code`.
