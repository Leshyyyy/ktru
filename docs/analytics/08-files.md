# 8. Обработка входных файлов

После загрузки система не угадывает структуру файла, а предлагает сопоставление колонок, которое пользователь подтверждает. Так реальные спецификации с произвольными заголовками не ломают обработку.

| Формат | Как читаем | Особенности |
| --- | --- | --- |
| xlsx | `openpyxl` в режиме только чтения | Несколько листов, объединённые ячейки (берём значение верхней левой), заголовок не всегда в первой строке, пустые строки и подитоги |
| csv | `csv` + определение кодировки и разделителя | UTF-8, UTF-8 BOM, Windows-1251; разделители `;`, `,`, табуляция |
| pdf | `pdfplumber`: таблицы, иначе текст по строкам | Таблицы, переносящиеся на другую страницу, сканы. OCR (tesseract) включается только если текстового слоя нет |

**PDF и большие файлы.** Загрузка (`POST /files`) должна отвечать за секунды при любом размере, иначе PDF на 60 страниц даст тот самый 504. Поэтому для предпросмотра разбираются только первые 3 страницы, `row_count` у PDF равен null, а весь файл разбирается уже в задаче. Если там окажется больше 1000 позиций, задача завершается со статусом `failed` и `error_code = limit_exceeded`.

**Роли колонок**

| Роль | Обязательна | Примеры заголовков |
| --- | --- | --- |
| `name` — наименование | да | Наименование, Товар, Позиция, Наименование товара (работы, услуги) |
| `description` — описание | нет | Описание, Технические требования |
| `characteristics` — характеристики | нет | Характеристики, Параметры, ТХ |
| `quantity` — количество | нет | Кол-во, Количество |
| `unit` — единица | нет | Ед. изм., Единица измерения |
| `ignore` | — | Любая другая колонка |

**Как предлагаем роли.** Сначала словарь заголовков (точное и нечёткое совпадение), затем эвристика по содержимому (длинный текст — наименование или описание, числа — количество, короткие слова «шт», «кг» — единица). Пользователь всегда может переназначить. LLM для этого шага не нужна.

**Как собирается `raw_text`.** Склейка значений колонок `name`, `description`, `characteristics` через пробелы в порядке слева направо. Исходные значения колонок параллельно хранятся в `items.raw_row`, чтобы экспорт мог вернуть файл в исходном виде с добавленными колонками.

**Очистка перед ML**

- Удалить пустые строки, строки «Итого», повторяющиеся заголовки таблицы на новых страницах PDF.
- Нормализовать пробелы и неразрывные пробелы, привести кавычки к одному виду; регистр не менять (в моделях он несёт смысл).
- Дубли не удалять: каждая строка — отдельная позиция; дедупликация нужна только внутри ML-конвейера для экономии вычислений.

**Крайние случаи (обязательно проверить тестами)**

- Файл без строк данных → `file_unreadable`.
- Две колонки с ролью `name` → `mapping_invalid`.
- Ячейка `name` пустая, но `description` есть → позиция создаётся, наименование извлекает ML.
- Длинный текст больше 2000 символов → обрезается для эмбеддинга, полный текст сохраняется.
- Файл больше 5000 строк или больше 1000 выбранных → `limit_exceeded` с подсказкой разбить файл.
