# 3. Архитектура

Пользователь общается только с API, а вся тяжёлая работа уходит в очередь и выполняется воркерами. ML-конвейер — один блок со своим интерфейсом, который можно развивать отдельно от остального.

&#91;embedded content: архитектура · 7 сервисов, ML за одним интерфейсом\]

Конвейер внутри ML-воркера идёт сверху вниз; реранкер включается только для позиций, где быстрый поиск не уверен.

| Сервис | Что внутри | Профиль compose |
| --- | --- | --- |
| `frontend` | React SPA за nginx | по умолчанию |
| `api` | FastAPI, ничего тяжёлого не считает | по умолчанию |
| `worker-io` | Celery, очередь `io`: разбор файлов, экспорт, импорт каталога | по умолчанию |
| `worker-ml` | Celery, очередь `ml`: `Pipeline`, модели загружены в память | по умолчанию |
| `beat` | Celery beat, раз в минуту запускает `watchdog` | по умолчанию |
| `postgres` | Postgres + pgvector + pg\_trgm | по умолчанию |
| `redis` | Брокер Celery | по умолчанию |
| `llm` | Локальный LLM-сервер, OpenAI-совместимый | `gpu` или `llm` |
| `mock` | Prism по `openapi.yaml`, для фронтенда | `mock` |

Тома: `pgdata` (база), `uploads` (загруженные файлы), `models` (веса моделей, чтобы не скачивать при каждом запуске).
