# AI-классификатор КТРУ

Кейс-чемпионат B2B-РТС, задача 5. Пользователь загружает спецификацию закупки (xlsx, csv, pdf), подтверждает роли
колонок, система асинхронно извлекает атрибуты и подбирает код КТРУ: топ-3 с уверенностью 0–1 и пояснением, какие
характеристики совпали. Человек подтверждает или правит код и выгружает файл.

## Запуск

Нужен Docker с Compose, 8 ГБ оперативной памяти и около 4 ГБ на диске. Интернет нужен при сборке и первом запуске.

```bash
cp .env.example .env
docker compose up --build
```

Интерфейс — http://127.0.0.1:8080, API — http://127.0.0.1:8000/api/v1 (порты — `WEB_PORT` и `API_PORT` в `.env`;
на Windows 8000 бывает занят системой — тогда, например, `API_PORT=18000`).

По умолчанию работает настоящий ML (`PIPELINE=real`) на полном каталоге КТРУ:

- **Первая сборка — около 10 минут.** В образ ML-воркера ставится torch (CPU-сборка) и скачивается модель
  эмбеддингов `intfloat/multilingual-e5-small` (~470 МБ, ревизия и хеши закреплены).
- **Первый запуск — ещё несколько минут.** Контейнер `migrate` скачивает каталог КТРУ (открытый датасет ЕИС,
  ревизия и sha256 закреплены) и загружает его в базу. ML-воркер один раз считает эмбеддинги каталога в pgvector.
  Пока он готовится, интерфейс показывает «Система готовится». Следующие запуски ничего не скачивают.
- **Без доступа к Hugging Face при первом запуске** система не падает. Она работает на заглушке с кодами `99.99.*`,
  причину показывает `GET /api/v1/health`. Когда доступ появится, снова запустите `docker compose up`.

Что можно поменять в `.env`:

- `PIPELINE=stub` — заглушка ML на маленьком каталоге, без скачивания; удобно для фронтенда и бэкенда;
- `EMBEDDER_MODEL=-` — без эмбеддингов: поиск на TF-IDF, меньше памяти;
- ключи LLM не нужны. Без них всё работает, `RERANKER=llm` (Jev через OpenRouter) — по желанию.

### ML: как выбирается код

Внутри одного кода ОКПД2 позиции КТРУ называются одинаково («Ноутбук», «Шприц») и различаются обязательными
характеристиками, а по тексту КТРУ категорию живого названия товара угадать трудно. Поэтому две ступени:

1. **Категория ОКПД2** — по 106 тыс. реальных карточек товаров портала поставщиков (СТЕ), которым ОКПД2 поставили
   сами поставщики: ближайшие по названию карточки голосуют за свой код.
2. **Позиция КТРУ внутри категорий** — поиск по наименованию КТРУ (TF-IDF и нечёткое сравнение) и сверка
   характеристик: числа с единицами («объём 5 мл» против «> 3 и ≤ 5»), значения из списка, да/нет.
3. **Уверенность** — калибратор (логистическая регрессия + изотоническая калибровка): «0,8» означает, что такие
   ответы верны примерно в 80% случаев. Зону green / yellow / red бэкенд считает по порогам из `/config`.

Ручные решения сохраняются в `confirmed_examples`; ML принимает их через `add_examples` и для того же текста
сразу отдаёт подтверждённый код (подключение в воркере — `backend/core/processing.py`).
Эмбеддинги наименований (`intfloat/multilingual-e5-small`) — смысловая близость в поиске; векторы хранятся в
`catalog_items.embedding` (pgvector, `vector(1024)`) и считаются один раз при первом старте ML-воркера.

### Качество (полный КТРУ: 54 190 позиций для поиска, без ключей LLM, 2 ядра CPU)

| Набор | Что проверяет | Результат |
| --- | --- | --- |
| 1000 реальных названий товаров (СТЕ) | ОКПД2 верный | **75,5%** (простой поиск по КТРУ — 41%) |
| те же + 6 характеристик в строке | ОКПД2 верный | **76,8%**; 70–212 с на 1000 позиций (ТЗ: < 300) |
| 700 размеченных строк (синтетика по КТРУ) | точный код / любой допустимый | **87,0%** / 93,7% (ТЗ: ≥ 85%), ОКПД2 98,1%, атрибуты 96,2%, ECE 0,038 (ТЗ: ≤ 0,05) |

Ответы с уверенностью ≥ 0,7 — около четверти позиций — верны по ОКПД2 в 94% случаев: их можно принимать почти
не глядя, остальное система честно отдаёт человеку. Подробности, методика и все перепроверки — `ml/CLAUDE.md`.

### Данные

- КТРУ — официальная выгрузка ЕИС (`ml/ktru_xml.py`) или её копия в открытом датасете
  `dantetemplar/zakupki-dataset` (совпадение 99,68%, использование согласовано с жюри).
- Карточки СТЕ портала поставщиков Москвы — тот же датасет; использование согласовано в команде.
  Из них обучены модель категорий и словарь марок (`ml/models/`).
