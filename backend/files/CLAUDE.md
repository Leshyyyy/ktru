# backend/files — Модуль разбора входных файлов и экспорта

Владелец: Донир. Зона: разбор спецификаций (xlsx, xls, csv, pdf), сопоставление колонок, подготовка `raw_text` и `raw_row`, экспорт результатов.

## Структура

- `schemas.py` — Pydantic-модели по `contracts/openapi.yaml` (`FileInfo`, `Sheet`, `ColumnInfo`, `ColumnRole`, `LayoutHint`, `ParsedRow`).
- `roles.py` — функция `suggest_roles`: определение ролей колонок по словарю заголовков и содержимому.
- `reader.py` — `read_file(path) -> FileInfo`: быстрый предпросмотр (< 2 с) для `POST /files`.
- `parser.py` — `parse_rows(path, sheet, header_row, mapping) -> list[ParsedRow]`: полный разбор для Celery `parse_file`.
- `hash.py` — вычисление хеша структуры колонок (`layout_hint`) и SHA-256 файла (`duplicate_of_job_id`).
- `export.py` — генерация файлов экспорта (`source`, `xlsx`, `csv`, `json`) с экранированием формул.
- `tests/` — модульные тесты парсеров, экспорта и краевых случаев.
- `../../tests/e2e/` — сквозные тесты конвейера («загрузка → задача → правка → экспорт»).
- `../../tests/fixtures/` — спецификации на 100 и 1000 строк (`specification_100.*`, `specification_1000.*`).
- `../../tests/generate_test_specs.py` — генератор реалистичных спецификаций с краевыми случаями.
- `../../tests/benchmark_1000.py` — нагрузочный бенчмарк 1000 строк (Критерий 3).

## Правила и контракты

1. **Скорость `read_file`**: для PDF разбираются только первые 3 страницы, `row_count` равен `None` (`null`). Для XLSX используется `python-calamine`.
2. **Роли колонок**: ровно одна колонка `name`, не более одной `quantity` и `unit`. Нарушение маппинга вызывает `MappingInvalidError`.
3. **Формирование `raw_text`**: склейка непустых значений колонок `name`, `description`, `characteristics` через пробел в порядке слева направо. Исходная строка целиком сохраняется в `raw_row`.
4. **Очистка данных**:
   - Пропускать пустые строки и строки «Итого», «Всего».
   - Нормализовать множественные и неразрывные пробелы, приводить кавычки к парным «»/"", не менять регистр символов.
   - Не удалять дубликаты строк (каждая строка — отдельный `item`).
   - Лимиты: максимум 1000 позиций в задаче, максимум 5000 строк в файле.
5. **Безопасность экспорта**:
   - В CSV все ячейки, начинающиеся со знаков `=`, `+`, `-`, `@`, экранируются ведущим апострофом `'`.
   - В XLSX числовые формулы не исполняются, ячейки записываются в текстовом формате (`cell.data_type = 's'`).
   - Заголовок `X-Unreviewed-Count` передаёт количество непроверенных строк; при `allow_unreviewed=False` — 409 `unreviewed_items`.
6. **Запуск тестов и замеры**:
   - `pytest backend/files/tests` — модульные тесты парсеров и экспорта.
   - `pytest tests/e2e` — сквозные e2e-тесты конвейера.
   - `python tests/benchmark_1000.py` — нагрузочный замер 1000 позиций (Критерий 3 матрицы приёмки).
